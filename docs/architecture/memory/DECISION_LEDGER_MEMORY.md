# DECISION_LEDGER_MEMORY.md

| ID | Decision | Status | Reason | Impact |
|---|---|---|---|---|
| M-001 | Build `memory_items` from zero | accepted | Avoid coupling to legacy `rag_memories` | New schema, new migration, cleaner target architecture |
| M-002 | Scope is all 5 canonical actions | accepted | Align implementation with canonical module contract | No placeholder actions left in target module |
| M-003 | `search_memory` defaults to `status='active'` | accepted | Safer default behavior and cleaner user-facing semantics | Explicit override required for non-active search |
| M-004 | Default values: confidence=0.8, importance=0.5, durability=stable | accepted | Keeps v1 practical without overfitting caller behavior | Deterministic inserts when caller omits optional values |
| M-005 | `source_thread_id` is required for `store_memory` | accepted | Thread-aware memory is core to the new design | Store validation becomes stricter |
| M-006 | `source_message_id` is recommended, not universally hard-required in v1 | accepted | Some valid v1 stores may not map to one message cleanly | Allows controlled flexibility |
| M-007 | `recall_memory` uses strict filter intersection | accepted | Predictable structural recall semantics | Fewer ambiguous recall results |
| M-008 | `promote_memory` only supports `recent -> long_term` | accepted | Simpler v1 semantics and easier debugging | Invalid transitions fail clearly |
| M-009 | `category` remains controlled free-text | accepted | Product flexibility now, stronger taxonomy later | Enforce normalization without hard enum |
| M-010 | `evidence_refs` minimum shape is `type`, `ref`, optional `thread_id`, `message_id`, `note` | accepted | Keeps v1 evidence machine-readable | Easier future upgrades |
| M-011 | Inference safety v1 uses Romanian heuristic filter | accepted | Cheap v1 safety barrier, stronger classifier deferred | Some content rejected before insert |
| M-012 | Walker fixtures are persisted and clearly labeled, not aggressively cleaned up | accepted | Better rerun stability and debugging | Requires test metadata discipline |
| M-013 | Claude must work through explicit sub-processes / skills / pipelines | accepted | Reduce chaos and memory drift | Mission becomes reproducible across sessions |
| M-014 | Embedding column: `vector(1536)`, nullable, partial ivfflat cosine index with lists=100 | accepted (Phase-4, 2026-04-20) | Matches OpenAI text-embedding-3-small / ada-002 dim; nullability lets structural `recall_memory` bypass embedding cost; partial index skips unembedded rows | Downstream handlers must detect NULL embedding before semantic search; index retune required when row count grows large |
| M-015 | Reuse existing `public.rag_durability_enum` for `durability` column | accepted (Phase-4, 2026-04-20) | Enum already exists with {stable, seasonal, volatile}; creating a parallel enum would fragment durability ontology. Enum is schema-level, not row-level coupling to `rag_memories` | No out-of-scope write to legacy table; consistent durability semantics across old and new memory surfaces |
| M-016 | `source_thread_id` FK uses `ON DELETE RESTRICT`, not `SET NULL` | accepted (Phase-4, 2026-04-20) | Column is NOT NULL — `SET NULL` would raise a not-null violation at delete-time, masking semantics. RESTRICT declares intent explicitly: thread hard-delete requires prior app-layer memory cleanup | GDPR-style thread erasure must be a deliberate, auditable app operation; cannot silently cascade |
| M-017 | `idempotency_key` is `TEXT NOT NULL UNIQUE`, format `{action}:{execution_context_id}:{step_id}`, applied only on row-creating actions (`store_memory`, `supersede_memory`) | accepted (Phase-4, 2026-04-20) | `promote_memory` mutates in place (naturally idempotent); `search_memory` / `recall_memory` don't write; only create-row actions need DB-level idempotency | Handler-side responsibility for replay safety on non-write actions; clean single-source for DB-level duplicate suppression |
| M-018 | `memory_status_enum = {active, superseded, expired, archived}` | accepted (Phase-4, 2026-04-20) | `active` + `superseded` are strictly needed by v1 `supersede_memory`; `expired` + `archived` are reserved lifecycle sinks so future code does not require another enum migration | Wider enum now = no ALTER TYPE ADD VALUE later for lifecycle work |
| M-019 | `category` enforced at DB level with regex `^[a-z][a-z0-9_]{0,63}$` | accepted (Phase-4, 2026-04-20) | Decision #9 is DB-enforced not handler-enforced to make the normalization contract unbypassable and keep `GROUP BY category` reports stable | Malformed categories fail insert, never silently propagate |
| M-020 | Migration uses guarded `DO $$ IF NOT EXISTS ... CREATE FUNCTION` for `set_updated_at()` instead of `CREATE OR REPLACE` | accepted (Phase-4, 2026-04-20) | Live DB dry-run surfaced ownership conflict: `must be owner of function set_updated_at`. Guarded creation keeps the migration portable to fresh DBs while never trying to replace the existing live helper | Migration is safe to run on any environment (live, staging, test) without elevated privileges |
