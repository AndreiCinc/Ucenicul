## A. Canonical folder shape (single source of truth)

Every populated workflow folder MUST have this exact tree:

```
workflows/WF-XX-01_<Name>/
├── README.md                         # navigation + status card
├── workflow/
│   ├── <WF-XX-01>_blueprint.json     # exact n8n export (canonical artifact)
│   └── last_sync.json                # { n8n_updatedAt, sha256, sync_agent }
├── docs/
│   ├── node_map.md                   # every n8n node: id, type, role, upstream/downstream
│   ├── contract.md                   # input envelope, output envelope, allowed_next_stage
│   ├── flow.md                       # happy path, error paths, context-error paths
│   ├── handoffs.md                   # who calls this WF, who it calls next
│   └── sql_policy.md                 # parameterized vs inline rationale per query
├── sql/
│   ├── <query_name>.sql              # one file per Postgres query used in the WF
│   └── README.md                     # index of queries + param signatures
├── scripts/
│   ├── <code_node_name>.js           # one file per n8n Code node
│   └── README.md                     # index of code nodes + exported helpers
├── tests/
│   ├── fixtures/                     # WF-specific fixtures (symlink to testing/fixtures/ if shared)
│   ├── unit/                         # unit tests for scripts/*.js
│   ├── integration/                  # WF↔WF integration tests
│   └── README.md                     # how to run
├── reports/
│   ├── AUDIT_REPORT.md               # last audit vs live n8n (generated by wf-sync skill)
│   ├── BUILD_REPORT.md               # build / population log
│   ├── CLOSURE_REPORT.md             # sign-off once WF is populated + verified
│   ├── FIX_LOG.md                    # per-fix entries during population
│   ├── WORK_LOG.md                   # freeform notes during active work
│   ├── POST_IMPORT_AUDIT.md          # diff after re-importing into n8n (if done)
│   ├── REMEDIATION.md                # open issues with plan + owner
│   ├── TEST_REPORT.md                # latest test-run summary
│   ├── TEST_AFTER_IMPORT.md          # tests after re-import (if done)
│   └── PENDING_WIRING.md             # known-incomplete edges (e.g. RC-01 → MO-01)
└── assets/
    └── README.md                     # index of screenshots / diagrams (optional)
```

**Enforcement.** The `wf-sync` skill (§D.1) refuses to mark a workflow `populated` unless every REQUIRED file exists with a minimum non-empty payload. Empty subfolders remain allowed as placeholders; empty files are not.

## B. Per-.md content contract

Each `.md` in the folder has a minimum required content contract. Anything less fails the `wf-sync` health check.

### B.1 `README.md` (navigation + status card)

Required sections, in order:

1. **Title** — `# WF-XX-01 <Canonical Role>` (must match live n8n workflow name modulo punctuation).
2. **Status card** — one-line block with fields: `n8n_id`, `n8n_active`, `n8n_updatedAt`, `repo_status` (`scaffold` | `populated` | `drift` | `obsolete`), `last_sync`, `owner`.
3. **Role** — 2–4 sentences: what this workflow does in the target pipeline.
4. **Authority** — pointer to `docs/architecture/n8n_Workflow_Mapping.md` + relevant `Module_Spec_*.md`.
5. **Inputs** — short form of the input envelope (full form in `docs/contract.md`).
6. **Outputs** — short form of the output envelope + `allowed_next_stage`.
7. **Subfolder tour** — table of subfolders with one-line purpose each.
8. **Open gaps** — bullet list of known-incomplete items, with pointer to `reports/PENDING_WIRING.md` or `reports/REMEDIATION.md`.
9. **Last updated** — ISO date.

### B.2 `docs/node_map.md`

Table with one row per n8n node. Columns: `node_id`, `name`, `type`, `role` (1 line), `upstream_nodes`, `downstream_nodes`, `disabled` (bool), `notes`. Totals row at bottom: total nodes, total code nodes, total Postgres nodes, total switch nodes.

### B.3 `docs/contract.md`

Four sections, in this order:

1. **Input envelope.** JSON shape with field names, types, and whether required. Must cite the producing upstream WF.
2. **Output envelope.** Same shape + `status_kind`, `result_type`, `payload`, `allowed_next_stage`, `idempotency_key`, `sha256_digest`.
3. **Invariants.** Bullet list: idempotency rule, replay rule, privacy rule, lineage rule.
4. **Error shapes.** Named error envelopes (validation error, context-missing error, lineage error, timeout error) with their payloads.

### B.4 `docs/flow.md`

Three paths, each as a short linear list of node names:

- **Happy path.**
- **Error path.**
- **Context-error path** (when the execution context does not match).

Any `if` / `switch` junctions are written as inline decisions (`→ Route Valid (switch): true → … / false → …`).

### B.5 `docs/handoffs.md`

Two tables:

- **Called by.** Upstream WFs. Columns: WF code, node name in upstream, envelope shape.
- **Calls next.** Downstream WFs. Columns: WF code, node name here, envelope shape, `allowed_next_stage` value.

### B.6 `docs/sql_policy.md`

Per query in `sql/`, one row: `query_file`, `node_id`, `param_mode` (`parameterized` | `inline_sanitized`), `rationale_if_inline`. Follows the canonical policy defined in `docs/architecture/n8n_Workflow_Mapping.md` §5 (referenced in CLAUDE.md).

### B.7 `sql/README.md`

Index of `.sql` files. Each row: `file`, `purpose`, `param_signature`, `source_node`.

### B.8 `scripts/README.md`

Index of `.js` files (one per n8n Code node). Each row: `file`, `node_id`, `exports`, `consumes`, `produces`.

### B.9 `tests/README.md`

Three sections: **Fixtures**, **Unit tests**, **Integration tests**. Each section: how to run, what's covered, what's NOT covered.

### B.10 `reports/*.md`

Every report file uses a 5-section template: **Context**, **Findings**, **Actions Taken**, **Open Items**, **Next Step**. Enforced by the report templates under `inventory/report_templates/` (to be added when `wf-sync` is installed).

## C. Top-level `workflows/README.md` contract

The top-level index MUST contain:

1. **Folder-shape cheat sheet** — same table as §A.
2. **Active workflow folders** — one row per live workflow, columns: `Code`, `Folder`, `Role (n8n name)`, `Skeleton`, `Populated?`, `Last sync`, `Gap severity`.
3. **Non-workflow entries** — one row per `_ARCHIVED_*` or `_OBSOLETE_*` folder.
4. **Authority pointer** — `Subordinate to docs/architecture/n8n_Workflow_Mapping.md`.

No decorative prose beyond these sections.

## D. Maintenance — skills + agents

The maintenance load is non-trivial: 10 WF folders × ~8 .md + 1 JSON + multiple SQL/JS files each ≈ 100+ artifacts. Hand-maintenance will drift within weeks. The standardization binds the content to skills that re-derive the artifacts from live n8n.

### D.1 Skill: `wf-sync`

**Purpose.** Refresh a single WF folder (or all of them) from the live n8n state. The skill is idempotent: running it twice produces the same output.

**Inputs.** WF code (e.g. `WF-TR-01`) or `--all`.

**Outputs (per WF):**

- `workflow/<WF>_blueprint.json` — overwritten with fresh export
- `workflow/last_sync.json` — updated with new `n8n_updatedAt`, new `sha256`, skill version
- `docs/node_map.md` — regenerated table (preserves manual `notes` column via a `# MANUAL ROWS BELOW` divider)
- `docs/contract.md` — regenerated **Input envelope**, **Output envelope** sections; manual **Invariants** and **Error shapes** preserved below a `# MANUAL CONTENT BELOW` divider
- `docs/sql_policy.md` — regenerated with current query list; manual rationale preserved
- `sql/*.sql` — each file overwritten if query text changed (reports the diff in `reports/FIX_LOG.md`)
- `scripts/*.js` — each file overwritten if code text changed (reports diff)
- `reports/AUDIT_REPORT.md` — appended with a new dated entry: what changed, what preserved, what requires human review
- `README.md` — status card updated; rest preserved

**Refusal modes.**

- Refuses to run if `workflow/<WF>_blueprint.json` exists AND `last_sync.json` is newer than 24h AND no `--force` flag.
- Refuses to overwrite files inside `docs/` that lack the manual-divider convention — it emits a REMEDIATION entry instead.
- Refuses to populate a WF folder that does not yet exist; creation is a separate operation (see §D.2 `wf-scaffold`).

**Location.** `.claude/skills/wf-sync/SKILL.md` (to be created when §F §2 of the coverage audit is executed).

### D.2 Skill: `wf-scaffold`

**Purpose.** Create a new WF folder from scratch following §A exactly. Used once per new workflow (e.g. WF-RC-01, WF-MO-01 in this pass).

**Inputs.** WF code + canonical role name (e.g. `WF-RC-01 Response Composer`).

**Outputs.** The full empty skeleton per §A, with templated README + all required report template files, each carrying only their section headers (no placeholder prose).

**Refusal modes.** Refuses if the WF code already exists as a folder. Refuses if the code is not registered in the workflows index.

**Location.** `.claude/skills/wf-scaffold/SKILL.md`.

### D.3 Skill: `wf-audit`

**Purpose.** Read-only audit. Regenerates `inventory/WORKFLOW_COVERAGE_AUDIT.md` and an `inventory/WORKFLOW_SCORECARD.json` from the live n8n state and the repo. Never modifies any WF folder.

**Inputs.** none (or `--since <iso_date>` for a differential audit).

**Outputs.**

- `inventory/WORKFLOW_COVERAGE_AUDIT.md` — overwritten
- `inventory/WORKFLOW_SCORECARD.json` — overwritten with Alignment / Coverage / Recency scores

**Cadence.** Can be scheduled (see §D.4 agent).

**Location.** `.claude/skills/wf-audit/SKILL.md`.

### D.4 Agent: `wf-maintainer` (scheduled)

**Role.** A thin agent that runs on a schedule (daily or every push to `workflows/`). It:

1. Runs `wf-audit` → writes `inventory/WORKFLOW_SCORECARD.json`.
2. If Coverage < 9 or Alignment < 8, opens a `REMEDIATION` entry in each affected WF folder and in `PROGRESS_LOG.md`.
3. If any n8n `updatedAt` is newer than the repo's `last_sync.json` by more than 7 days, runs `wf-sync --all` (optionally gated behind manual approval in STATE).
4. Never mutates n8n.

**Implementation.** A short markdown agent definition under `.claude/agents/wf-maintainer/AGENT.md` + a cron entry created by the `schedule` skill (already available — see `available_skills`).

### D.5 Skill: `consolidate-memory` (existing)

Reused as-is to merge duplicate or stale notes inside `inventory/` after every `wf-sync` run. Already installed.

## E. Reduced template for legacy / deprecated / obsolete workflows

For entries like `_ARCHIVED_Executor_Closer_stub/`, `DEPRECATED__WF-MO-01_langchain_stub` (if it ever gets a repo folder), and the monolith orientation doc (`docs/archive/brain_main_monolith_orientation.md`), the reduced template applies:

- `README.md` — Title, `OBSOLETE` or `ARCHIVED` label, reason, successor pointer, last-observed-date. No `workflow/`, `sql/`, `scripts/`, `tests/` subfolders.
- No `wf-sync` runs against these entries. They are explicitly excluded by the skill's refusal list.

## F. Naming conventions (locked)

- **Workflow code.** `WF-<TWO_LETTER_CODE>-01` (always `01`; new versions get `02`, `03` rather than renames). Existing codes: `DI, EC, ME, OR, PL, RA, SU, TR, RC, MO, 00` (cron), `01` (inactive receiver).
- **Folder name.** `WF-<code>-01_<PascalCase_or_snake_with_canonical_role>`. Must match the live n8n workflow name modulo punctuation (e.g. n8n `WF-SU-01 State / Persistence Updater` → folder `WF-SU-01_State_Persistence_Updater`).
- **Blueprint file name.** `<WF-code>_blueprint.json` (lowercase code prefix is NOT allowed; must be `WF-TR-01_blueprint.json`).
- **Deprecation prefix.** `DEPRECATED__` (double underscore) in n8n; `_ARCHIVED_` prefix for repo folders that are vestigial but undeletable.

## H. Acceptance criteria

The standardization is considered accepted when:

1. `workflows/README.md` references this document and lists every active WF with `populated` status.
2. Every WF folder passes `wf-sync --dry-run` (all required files exist, all contracts satisfied).
3. `inventory/WORKFLOW_SCORECARD.json` shows Alignment ≥ 8 / 10, Coverage ≥ 9 / 10, Recency ≥ 8 / 10.
4. `wf-maintainer` agent schedule exists and has run at least once successfully.
5. `docs/archive/brain_main_monolith_orientation.md` exists and is linked from `README.md` §"Current Implementation Status".
